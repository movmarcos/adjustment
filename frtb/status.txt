Problem Description:-

SABRE provides curvature sensitivities for all products, but Raptor output appears filtered to include only trades associated with OrgManager optionality enabled values (for example, FRTB_Optionality = Yes).

Action Taken:-

Curvature optionality logic was implemented
In fact_frtbsa_sensitivity_measures_sbm_official.sql:36, filtering now uses dimension_typology_group for FRTB_Optionality.

CURVATURE records are included only when option_desc = 'true' (case-insensitive), as shown at fact__frtbsa_sensitivity_measures_sbm_official.sql:46.
DELTA/VEGA continue using existing is_below_the_line_typology = false behavior.

Tested the fix using the following query, it looks fine.


SELECT
CASE
WHEN EXISTS (
SELECT 1
FROM dimension.typology_group tg
WHERE tg.typology_group = 'FRTB_Optionality'
AND UPPER(f.business_product_code4) = UPPER(tg.typology)
AND f.evaluation_date BETWEEN tg.effective_start_date AND tg.effective_end_date
AND (
LOWER(TRIM(COALESCE(tg.option_code,''))) IN ('y','yes','true','1','t')
OR LOWER(TRIM(COALESCE(tg.option_desc,''))) IN ('y','yes','true','1','t')
)
) THEN 'TRUE'
ELSE 'FALSE_OR_MISSING'
END AS optionality_flag,
COUNT(*) AS row_count
FROM fact.frtbsa_sensitivity_measures_sbm_official f
WHERE UPPER(f.sensitivity_type) = 'CURVATURE'
GROUP BY 1;
